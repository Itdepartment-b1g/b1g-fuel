# User management API and Redux

User request and response types live in `src/server/schema/users_schema.ts`. Frontend components and Redux use `import type`, so these contracts add no server code to the browser bundle.

Express exposes `GET /api/users`, `GET /api/users/options` and `POST /api/users`. All require a verified session and the global `super_admin` assignment from Postgres. Responses use private, no-store caching. Creation requires the application's Origin and is rate limited.

List query parameters: `page` (default 1), `page_size` (default 10; allowed values 10, 20, 50, 100), `search` (case-insensitive name or email search). Response: `{ users, total, page, page_size }`; every user includes the required `name`. Options return `{ companies, roles }`; roles have company scope only.

Creation requires `{ name, email, password }`; `company_id` and `role_ids` are optional. A name must contain 1–250 characters. Omit both assignment fields to create an account without a company or roles. Providing a company alone creates a membership without roles. `role_ids` can be omitted or empty; nonempty roles require `company_id` and must be distinct company-scoped roles (maximum 50). Omit unused fields rather than sending null or an empty company ID. The backend trims the name, normalizes email, validates supplied assignments, creates an email-confirmed Supabase account with display-name metadata, and saves the Prisma profile and optional membership with roles in a transaction. No global roles, invitation email or forced password-change flow. Configure backend-only `SUPABASE_SECRET_KEY` on the API service. The seed saves `SEED_SUPER_ADMIN_FULL_NAME` in the profile and metadata, defaulting to `Super Admin`. Login requires an existing admin-provisioned profile and preserves its name; neither password nor Google login creates missing profiles.

Auth and Postgres cannot share a transaction. Failed persistence triggers deletion of only the newly created Auth account. Failed cleanup logs its account UUID for operator reconciliation without credentials. A process interruption between the two systems can also leave an account requiring reconciliation. Duplicate accounts return 409; existing accounts are never modified or adopted.

Redux exports `listUser(query)`, `getUserOption()`, `createUser(input)`, `resetUsers()`, `clearCreateStatus()` and `selectUser` from `src/lib/store/users-slice.ts`. List, options and creation have separate statuses/errors. Errors retain HTTP status for redirecting on 401 or showing access denied on 403. List/options ignore older responses and support cancellation.

`CreateUserInput`, `CreateUserResponse` and `UserSummary` share the required name through the backend and Redux. Login and session responses use the saved profile name. Accounts without a Prisma profile are rejected before the session response is served. Swagger documents these request and response fields.

Keep form values local. `createUser` uses a manual thunk to keep passwords absent from dispatched plain actions and Redux state. Await `dispatch(createUser(input))` directly; it returns the created user or rejects with `{ status, message }`. Fetch thunks support `.unwrap()`. After successful creation, dispatch `listUser(currentQuery)` to refresh the current filter/page. Creation invalidates in-flight list results. Reset users on sign-out and abort pending reads when leaving the page.

No schema migration required. Configure Supabase/Postgres, apply existing migrations, seed a super-admin, and ensure companies and company roles exist for real creation. Live database/Auth integration must be verified separately. The Users UI includes search, table/card views, shared pagination and a creation dialog. The dialog requires name/email/password, confirms the password and permits optional company/role assignments. Success closes the dialog and refreshes the first page; errors keep form values for retry. `/users`, `/roles` and `/companies` require the verified global `super_admin` role at the page proxy, and the users API independently enforces that role. Super-admin sidebar navigation includes all registered dashboard pages without explicit page/permission grants. Ordinary users retain grant-based navigation and the authenticated dashboard home.

The Users repository exports named async functions: `list_user`, `get_user_filter_data`, `get_user_option`, `assignable_user`, and `create_user`. List snapshots and user creation retain their database transactions.

The Users service exports named async functions: `list_user`, `get_user_option`, `get_user_filter_option`, and `create_user`. Repository and Auth dependencies can be supplied directly to these functions for tests; no service factory or service object is exported.
